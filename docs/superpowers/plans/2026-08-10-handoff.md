## Ground rules

**Follow `AGENTS.md`.** This is a Next.js 16 codebase with breaking changes from
what you may have memorized. Read the relevant guide under
`node_modules/next/dist/docs/` before writing Next-specific code. Plan B touches
routes, metadata, and route handlers — check the docs for those.

**TDD, per the plans.** Every task is written as: failing test → run it and see
it fail → minimal implementation → run it and see it pass → commit. Do not skip
the "see it fail" step; a test that passes before implementation is testing
nothing.

**Commit per task**, using the message given in the task's final step. Every
commit message ends with:

```
Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
```

**Push when you finish**, or incrementally — the branch is already tracking
origin, so a plain `git push` works.

**Do not merge to `main`** and do not open a pull request. The owner will review
the branch.

**Vitest only collects `src/**/*.test.{ts,tsx}`.** Anything you want tested must
live under `src/`. `scripts/` holds thin orchestration only — that is why the
converter lives in `src/lib/notion/` and not next to the sync script.

## The one place the plan is uncertain

**Plan A, Task 8, Step 2.** The Notion client code was written against Notion's
published API documentation, not against the installed package's TypeScript
types — `@notionhq/client` was not installed when the plan was written.

Step 2 tells you to inspect the real SDK surface after `pnpm add` and prefer a
typed method (`client.dataSources.query(...)`) over the raw
`client.request({ path: "data_sources/.../query" })` escape hatch if one exists.
Do that check properly and note what you found in the commit message.

Everything else in Plan A is pure functions over fixture data, verifiable with
no network access at all.

## When you are blocked

If a task cannot be completed as written:

1. **Do not silently skip it** and do not weaken a test to make it pass.
2. Finish every other task that does not depend on it.
3. Report clearly: which task, which step, what you observed, what you tried.

Particularly: **never weaken `src/lib/notion/__tests__/idempotency.test.ts`**
(Plan A, Task 7). That test proves the sync produces byte-identical output on a
re-run. Without it, the 10-minute cron would commit and redeploy the site 144
times a day. If it fails, the determinism bug is in the pure modules from Tasks
3, 4, or 6 — fix it there.
